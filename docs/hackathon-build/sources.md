## Research conclusions versus implementation evidence

Additional inspected integration references: [USGS TNMAccess API overview](https://www.usgs.gov/faqs/there-api-accessing-national-map-data) identifies the downloadable-product catalogue API; [NRCS tabular/query tools](https://www.nrcs.usda.gov/conservation-basics/soil/tabular-data-query-tools) and [Soil Data Access service help](https://sdmdataaccess.nrcs.usda.gov/WebServiceHelp.aspx) identify the selected US soil route. Use fixed, bounded provider query templates and record source aggregation. [Philadelphia GSI Planning and Design Manual](https://water.phila.gov/gsi/planning-design/manual/) and [stormwater guidance](https://water.phila.gov/development/stormwater-plan-review/manual/) are selected sources for local design constraints and cost-estimation practice; actual unit-price values still need source extraction and date/region checks.

Confirmed: relevant public data/model/documentation families exist; structured output and browser float-buffer mechanisms exist; some providers impose meaningful access restrictions. Selected architecture: direct-source GIS preparation, conservative GPU model, explicit transfers, constrained search, evidence-bound AI and paired replay. Not yet established: exact hero data completeness, flood reduction, monetary benefits, device speed, supported user API accounts, operational costs or customer adoption.

The architecture deliberately keeps the full user experience while treating these as work to verify. A source URL is not a passed integration test, and an existing scientific method is not proof of this future implementation's accuracy.
